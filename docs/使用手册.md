# FitTrack 使用手册

> 这份是给使用者看的。技术实现、架构与算法细节见 `docs/开发文档.md`，开发约定见根目录 `CLAUDE.md`。

## 1. 两个版本

同一套功能做了两个版本，数据格式完全互通（JSON 可以互相导入），但**各自独立、不会自动同步**。

| | 网页版 | Mac 版 |
|---|---|---|
| 在哪用 | 浏览器打开 https://3148427574-cloud.github.io/FitTrack/ | 装 DMG，macOS 14+ |
| 适用 | Windows / 安卓 / iPhone / 任何浏览器 | 只在 Mac 上 |
| 数据存哪 | 浏览器本地（localStorage） | `~/Library/Application Support/FitTrack/` |
| API Key 存哪 | 浏览器本地 | 系统钥匙串 Keychain |
| 同步 Apple 提醒事项 | ❌ 没有（用「导出 .ics」导入系统日历代替） | ✅ 有 |
| AI 生成计划 / AI 对话 | ✅ | ✅ |

网页版可以直接「装」成桌面应用：Chrome / Edge 在地址栏右侧点「安装」；iPhone 用 Safari 的「分享 → 添加到主屏幕」。装完有独立图标、全屏运行、断网也能打开（界面能开，AI 用不了）。

## 2. 上手三步

1. **填个人资料**：设置 → 个人资料（性别 / 年龄 / 身高 / 每周训练天数 / 活动系数）。这些直接决定饮食热量和配重，先填对。
2. **定目标**：设置 → 目标。选增肌 / 减脂 / 维持，填目标体重和每周增减速度。
3.（可选）**填三大项极限**：设置 → 三大项极限。填了配重更准；不填也行，有训练记录后点「用历史估算」自动算。
4.（可选）**填 DeepSeek API Key**：设置 → AI 设置。不填也能用，只是生成计划会走固定模板，AI 助手不可用。

## 3. 侧栏七个页面

| 页面 | 干什么 |
|---|---|
| 概览 | 看体重/目标/记录数，看目标进度，生成并查看今日训练计划 |
| 训练 | 生成计划、导出日历、记录训练、完成/跳过计划、管理历史 |
| 饮食 | 每日热量与三大营养素目标、示例餐单、记录吃了什么、食物库 |
| 身体 | 录体重体脂腰围、看体重趋势图、看历史 |
| AI 助手 | 和 AI 聊训练/饮食问题，可让它提议修改你的资料 |
| 导入导出 | 粘贴或选文件导入历史数据，导出备份与日历 |
| 设置 | 个人资料、目标、三大项、训练偏好、API Key |

## 4. 逐页说明

### 4.1 概览

上方四张卡片：最新体重、目标体重、训练记录次数、身体数据条数。

**目标进度**：录入过身体数据后显示，告诉你离目标还差多少。

**今日训练计划**：点右上「生成今日计划」。有 API Key 时 AI 会结合你的训练历史和身体数据生成；没有 Key（或 AI 调用失败）自动回退到内置模板。生成完每张卡片列出动作、组数×次数、建议重量、预计消耗。

同一份计划（同一天同一个拆分）只会存在一条，重复点会提示「今日该计划已存在」。

### 4.2 训练

**生成今日计划**：和概览页那个按钮一样。

**导出 .ics 日历**：把待完成的计划导成日历文件。双击导入系统日历后，训练安排就出现在手机/电脑日历里。网页版没有「同步到提醒事项」（那是苹果系统独有），用这个代替。

**记录一次训练**：手动补记 —— 选拆分名、选动作、填组数/次数/重量。重量填 0 表示自重动作。

**进行中的计划**：列出所有待完成的计划，每条可以「完成」或「跳过」。
- 点「完成」会把计划落成一条训练历史（按计划里的组数×次数×重量记录），并更新你的 1RM 基准，影响下次配重。
- 点「跳过」只是标记，不影响配重。

**历史训练**：按时间倒序列出，最多显示最近 50 条（数据都在，只是列表截断）。每条可单独删除，右上「清空全部」一键清空 —— 两个操作都会二次确认。

### 4.3 饮食

**每日目标**：根据你的资料、目标和当前体重算出每天该吃多少热量、蛋白质、碳水、脂肪。

- 增肌 = 每日消耗 + 400 千卡，减脂 = 每日消耗 − 400 千卡，维持 = 每日消耗
- 蛋白质：增肌/减脂 2.0 g/kg，维持 1.6 g/kg；脂肪 0.9 g/kg；剩下的热量给碳水

**示例餐单**：从食物库里挑蛋白、碳水、脂肪含量最高的食物，按 4 餐给出建议克数。只是个示例搭配，不用照做。

**记录饮食**：选食物、填克数、点添加，记下今天吃了什么。

**食物库**：每 100g 的热量与三大营养素，内置 16 种常见食物。

### 4.4 身体

**趋势图**：录入 2 条以上体重数据后出现，横轴日期纵轴体重。

**录入今天**：填体重（必填）、体脂%（选填）、腰围 cm（选填），点添加。空着不填的项不会记成 0，会当成「没测」。

**历史记录**：倒序列出所有记录。

提示：体重这一项会被用于估算卡路里和配重，所以**至少要录一次**。没有身体记录时，系统会用你的「目标体重」代替。

### 4.5 AI 助手

顶部如果没有 Key，会有一条橙色提示，粘贴 `sk-...` 保存即可。Key 只存在你自己的设备上，不会上传到任何服务器（这站没有后端）。

能问什么：

- 动作替换：「杠铃卧推肩膀不舒服，能换成什么动作？」
- 动作规范、计划调整、饮食营养
- 直接说你的情况：「我想增肌增强力量，每周只能练 4 天」

**AI 可以提议修改你的资料**：当你说出长期的目标、身体数据或训练限制时，它会在回复下方附一张「建议更新个人资料」卡片，列出准备改什么（比如「每周训练天数：4 → 6」）。

- 点**应用**才会真正写入，点**忽略**就丢弃。
- 所有提议都会先过一遍范围校验（比如年龄只接受 10–90，身高只接受 120–250），越界会被夹到边界值。
- **它不会自动改你的任何数据**，必须你点确认。

聊天记录最多保留 40 条，超出的旧消息会被丢弃。「清空」按钮可清空全部聊天。

### 4.6 导入导出

**导入**：把 JSON 或 CSV 粘进文本框，点「导入 JSON」/「导入 CSV」；或者点「选择文件」直接选一个 `.json` / `.csv` / `.txt`（选完会自动按扩展名判断格式）。导入是**追加**，不会覆盖已有数据。

JSON 格式：

```json
{
  "version": "1.0",
  "source": "manual",
  "workouts": [
    {
      "date": "2026-09-10",
      "split": "推",
      "exercises": [
        { "name": "杠铃卧推", "sets": [{ "reps": 8, "weight_kg": 60 }] }
      ]
    }
  ],
  "bodyMetrics": [
    { "date": "2026-09-10", "weight_kg": 72.5, "bodyFatPct": 16, "waistCM": 80 }
  ]
}
```

- `split` 是拆分名，不填就记为「导入」。
- 重量字段两种写法都认：`weight_kg` 和 `weightKG`（所以 App 自己导出的文件能原样导回来）。
- 日期支持 `2026-09-10`、`2026/09/10`、`2026-09-10 08:30:00`，或带时区的 ISO 格式。
- 顶层还可以带 `chat` 数组（聊天记录），按 id 去重后合并。

CSV 格式（第一行是表头）：

```csv
date,weight_kg,body_fat_pct,waist_cm
2026-09-10,72.5,16,80
```

```csv
date,exercise,reps,weight_kg
2026-09-10,杠铃卧推,8,60
2026-09-10,杠铃卧推,8,62.5
```

- 表头里含 `weight_kg`（或 `weightkg` / `体重`）就当身体数据；含 `exercise`（或 `动作`）就当训练记录。
- 训练记录里同一天、同一个动作的多行会自动合并成一次训练的多组。
- 分隔符逗号、分号、Tab 都能识别。

**导出 JSON**：导出完整备份，文件名 `fittrack-export.json`（也可被 Mac 版读回）。

**导出 .ics**：同训练页的日历导出。

> ⚠️ **重要**：导入只恢复「训练记录 + 身体数据 + 聊天记录」，**不恢复**个人资料、目标、三大项、训练偏好这些设置。导出的文件里这些都带着，但导入时会忽略。所以换设备时，资料要手动重填一遍。

### 4.7 设置

**个人资料**：性别、年龄、身高、每周训练天数、活动系数（1.2 久坐 / 1.375 轻度 / 1.55 中度 / 1.725 高度 / 1.9 极高）。年龄输入框自动夹到 10–90，每周训练天数夹到 1–7。

**目标**：增肌 / 减脂 / 维持，目标体重，每周增减速度。

**三大项极限（1RM）**：填卧推/深蹲/硬拉的单次最大重量。留空就用训练历史自动估算；点「用历史估算」按钮可以把估算值直接填进去。旁边会显示「历史估算：卧推 100kg / 深蹲 140kg …」作为参考。

**训练偏好与约束**：写长期有效的限制，比如「每周只能练 4 天」「主项偏好低次数」「膝盖有旧伤，深蹲不要上太大重量」。这些会一直注入 AI 上下文，影响生成计划和对话建议。最多 12 条，每条最多 200 字。

**AI 设置**：粘贴 / 清除 DeepSeek API Key。

> 网页版设置页没有「保存」按钮 —— 改完即时生效并落盘。Mac 版底部有个「保存」按钮。

## 5. 数据存在哪 / 怎么备份

网页版的数据**只在这台设备的这个浏览器里**。换电脑、换浏览器、清浏览器数据、用无痕模式，都会看不到。所以：

- 想换设备：在旧设备「导出 JSON」，把文件传到新设备，「导入 JSON」（记得资料要重填）。
- 定期备份：偶尔导出一份存起来。

Mac 版的数据是本地 JSON 文件，可以用「导出 JSON」备份，也可以用这个文件搬到网页版（反之亦然）。

## 6. 数字是怎么算出来的

不看也不影响使用，但知道口径更放心。

**配重（每个动作建议多少公斤）** 按三级优先级：

1. 这个动作**最近 30 天**的实际训练记录，用 Epley 公式反推 1RM（超出 30 天没练，就退回历史最好成绩，避免一年前的巅峰数据把今天配重顶太高）
2. 没有记录，就用三大项锚点乘一个系数推导（比如站姿推举 = 卧推 × 0.62，腿举 = 深蹲 × 2.5）
3. 都没有，按体重比例给个保守起始值

然后 目标重量 = 1RM × 该次数的强度百分比（8 次约 79%），最后四舍五入到 2.5kg（方便上片）。自重动作（引体向上）不配重。

**卡路里**：MET 基线 × 体重 × 时长，再乘一个身高的「行程修正」（个子高动作行程长、消耗略多）。修正系数夹在 ±8% 以内 —— 这是个启发式估算，不是实测值，卡片上会显示用了多少系数。注意 MET 基线本身不随重量变化，所以大重量那天它会偏低，这是已知的粗估。

**饮食热量**：用 Mifflin-St Jeor 公式算基础代谢，乘活动系数得每日消耗，再按目标 ±400 千卡。

## 7. 常见问题

**换了台电脑，数据没了？**
数据存在浏览器本地，不会跟着账号走。用「导出 JSON」搬过去（资料需重填）。

**AI 用不了 / 一直报错？**
先确认设置里的 API Key 填了且没过期。网页版的 AI 是浏览器直连 DeepSeek 的，如果网络环境访问不了 `api.deepseek.com` 就会失败。没有 Key 时，训练计划仍然可以用（走固定模板）。

**生成的计划重复了？**
同一天、同一个拆分且还没完成的计划只会存在一条，重复生成会提示「今日该计划已存在」。想换一份，先把旧的「跳过」或「完成」。

**改了身高体重，配重变了？**
正常。配重和卡路里都依赖体重，身高影响行程修正系数。

**网页版为什么没有「同步到提醒事项」？**
那是苹果系统独有的接口，浏览器里没有。用「导出 .ics」再导入系统日历，效果类似。

**手机上能用吗？**
能。iPhone 用 Safari、安卓用 Chrome 打开网址都能正常用，还可以「添加到主屏幕」当 App 用。
