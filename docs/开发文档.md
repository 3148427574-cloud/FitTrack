# FitTrack 开发文档

> 本文档是 FitTrack 的常驻技术文档，随代码演进更新。定位、快速上手见根目录 `CLAUDE.md`；某次会话的快照总结见 `docs/2026-09-16-开发总结.md`。

## 1. 项目定位

个人健身与体重管理应用（SwiftUI，macOS + iOS 双 target）。核心能力：

- 根据**训练历史 + 身体数据变化**生成每日训练计划（AI 辅助，失败回退固定模板）
- 增肌/减脂/维持三种目标的饮食计划与食物库
- 身体指标记录（体重/体脂/围度）与趋势图
- 训练计划双向同步 Apple「提醒事项」
- 历史数据导入（JSON / CSV）
- 内置 AI 聊天助手（可读取用户真实数据）

## 2. 技术栈与构建

- SwiftUI + AppKit（macOS 仅入口层）；deployment **macOS 14 / iOS 17**
- 存储：**JSON 文件**（非 SwiftData / Core Data）
- AI：**DeepSeek** `chat/completions`（OpenAI 兼容），原始 URLSession，key 存 Keychain
- 提醒：EventKit（`EKReminder`）；HealthKit 仅 iOS 预留
- 构建：xcodegen 生成工程 + xcodebuild（`Package.swift` 是早期 SPM 遗留，**已弃用**）

```bash
cd /Users/frost/FitTrack
xcodegen generate
xcodebuild -project FitTrack.xcodeproj -scheme FitTrack -configuration Debug build
# 产物拷到 /Applications/FitTrack.app 后 open
```

## 4. 数据模型

根模型 `AppData`（`Models.swift:134`）：

```swift
struct AppData: Codable {
    var profile: UserProfile           // 性别/年龄/身高/活动系数/每周训练天数
    var goal: Goal                     // 增肌/减脂/维持 + 目标体重 + 周增减
    var workouts: [WorkoutSession]     // 已完成的训练历史
    var plannedWorkouts: [PlannedWorkout]  // 生成的训练计划
    var bodyMetrics: [BodyMetric]      // 体重/体脂/围度时间序列
    var foods: [Food]                  // 食物库（每 100g 营养）
    var exercises: [ExerciseDef]       // 动作库（名称/肌群/器械/是否自重）
    var dietLogs: [DietLog]            // 饮食记录
}
```

关键结构字段：

- `PlannedWorkout`：`date`、`splitName`、`exercises: [PlannedExercise]`、`status: WorkoutStatus`（planned/completed/skipped）、`note: String?`、`reminderID: String?`
- `PlannedExercise`：`name`、`targetSets`、`targetReps`、`targetWeightKG`
- `WorkoutSession`：`date`、`splitName`、`exercises: [ExerciseEntry]`、`durationMin`、`notes`
- `ExerciseEntry` / `SetEntry`：`name` + `sets: [SetEntry]`，每组 `reps` + `weightKG`（+ 可选 `rpe`）
- `BodyMetric`：`date`、`weightKG` 必填，`bodyFatPct/muscleMassKG/waistCM/chestCM/armCM/thighCM` 可选
- `ChatMessage`：`role`（"user"/"assistant"）+ `content`，独立于 `AppData`，单独持久化

## 5. 持久化与数据流

数据文件（`AppStore.defaultFileURL`，`AppStore.swift:67`）：

```
~/Library/Application Support/FitTrack/fittrack.json   # 主数据 AppData
~/Library/Application Support/FitTrack/chat.json        # AI 聊天历史 [ChatMessage]
```

- 编码：`ISO8601` 日期策略 + `prettyPrinted` + `sortedKeys`；写入用 `.atomic`
- `AppStore` 是唯一写入口；`@Published data` 与 `@Published chatMessages` 驱动 UI
- 首次启动若 `exercises`/`foods` 为空，用 `SeedData` 填充（`AppStore.swift:21`）
- 聊天历史上限 40 条，`trimChat(to:)` 保留最近 40

## 6. 核心机制

### 6.1 AI 计划生成 + 聊天（`AIService.swift`）

- 端点 `https://api.deepseek.com/chat/completions`，模型 `deepseek-chat`
- key 存 Keychain（service `com.frost.fittrack.ai`，account `deepseek-api-key`），UserDefaults 兜底（key `ai.deepseekKey`）
- `contextString(_:)` 组装上下文：性别/年龄/身高/体重 + 目标 + 动作库 + 身体趋势 + 近 20 次训练
- 计划生成：`generatePlan`（`temperature=0.3`，`maxTokens=4000`）→ system prompt 要求输出单 JSON → `parsePlan` 容错提取 `{...}` 后解码
- **回退链**：`generatePlanWithFallback` —— 无 key 或失败时走 `TrainingPlanner.generatePlan` 固定模板
- 聊天：`chat(history:context:)`（`maxTokens=8000`），system 含用户真实数据，角色顺序保证 user 在前

### 6.2 训练计划生成与渐进超负荷（`Engine.swift:117`）

- 拆分模板按每周训练天数选：≤2 天全身；3 天推/拉/腿；4 天上下肢 A/B；5 天混合
- 配重逻辑：`estimate1RM`（Epley：`w × (1 + reps/30)`，取历史组最大）→ 有历史用 `1RM × 0.75`，无历史用 `CalorieEstimator.defaultWeight`（按体重的比例表）→ 统一四舍五入到 2.5kg 倍数

### 6.3 卡路里估算（`Engine.swift:70`）

公式：`卡路里 = MET × 体重(kg) × 时长(小时)`；每组按 1.5 分钟（含休息）。

- MET：复合动作 6.0，自重动作 5.0，孤立动作 4.5（由动作名匹配集合判定）
- `defaultWeight`：按动作名 → 体重比例（深蹲 0.5、硬拉 0.6、卧推 0.4…），自重动作返回 0

### 6.4 提醒双向同步（`RemindersSync.swift`）

关联通过 `PlannedWorkout.reminderID == EKReminder.calendarItemIdentifier` 建立：

- **App → 提醒**：`syncToReminders` 创建 `EKReminder`（标题「🏋️ 训练：拆分名」、备注列动作×组×次×重量、dueDate 为当天），回写 `[计划ID: identifier]`
- **App 内点完成/跳过 → 提醒**：`markCompleted`（设 `isCompleted=true`）/ `markDeleted`（删除提醒）
- **提醒内点完成 → App**：`fetchStatus(ids:)` 拉取完成状态；`TrainingView` 监听 `EKEventStoreChanged` 自动拉回，另有「刷新状态」按钮兜底
- **无签名兜底**：`ICSExporter.ics(for:)` 生成 `.ics` 文本，可导入 Apple 日历

### 6.5 导入（`Importer.swift`）

- **JSON**：契约 `ImportSchema`（`version`/`source`/`workouts`/`bodyMetrics`），日期多格式兼容（ISO8601 / `yyyy-MM-dd` / `yyyy/MM/dd` / 带时间）
- **CSV**：`CSVParser` 手写解析（支持引号转义、`\t`/`;`/`,` 分隔符）；按表头自动识别两类：
  - 身体数据：含 `weight_kg`/`weightkg`/`体重` 列
  - 训练记录：含 `exercise`/`动作` 列（按「日期+动作」聚合多组）

### 6.6 饮食计划（`Engine.swift:26`）

- TDEE：Mifflin-St Jeor BMR × 活动系数（`Engine.swift:5`）
- `DietPlanner.targets`：增肌 TDEE+400 / 减脂 TDEE−400 / 维持 TDEE；蛋白质增肌 2.0g/kg、维持 1.6g/kg，脂肪 0.9g/kg，剩余热量给碳水
- `sampleMealPlan`：按 4 餐从食物库简单搭配蛋白/碳水/脂肪来源

## 7. 视图层（`Views.swift`）

`enum Section` 七页：概览 / 训练 / 饮食 / 身体 / AI 助手 / 导入导出 / 设置。

- `DashboardView`：目标进度 + `TodayPlanView`（AI 生成计划、异步 loading、结果提示）
- `TrainingView`：同步提醒、记录训练、完成/跳过（双向）、清空全部/逐条删除（均二次确认）
- `BodyView`：体重趋势图 + 录入
- `ImportView`：JSON/CSV 导入 + JSON 导出
- `AIChatView`：聊天 + 历史持久化 + 清空（带确认）
- `ProfileView`：设置（含 API key 管理）

## 8. 关键约定与坑

1. **给任何 Codable 结构体新增字段必须用 optional**（或提供默认值），否则旧 JSON 整体解码失败、数据全丢。这是本项目最易踩的坑。
2. 构建/约定的权威入口是根目录 `CLAUDE.md`，不要再用 `Package.swift`（SPM 遗留）。
3. macOS bundle id `com.frost.fittrack`（ad-hoc 签名 `CODE_SIGN_IDENTITY "-"`）；iOS `com.frost.fittrack.ios`（HealthKit entitlement）。
4. 日期格式统一 `ISO8601` 编解码；`DateFormatter` 需显式设 `en_US_POSIX` locale。
5. AI 计划里的自重动作 `targetWeightKG` 应为 0，`parsePlan` 会对「权重≤0 且非自重」的动作兜底补默认重量。
6. EventKit 提醒操作是 `@MainActor`（`RemindersSync` 标注），UI 调用需在 `Task { @MainActor in }` 内。
